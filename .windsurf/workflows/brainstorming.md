# 头脑风暴 (Brainstorming)

将粗略想法通过协作对话精炼为完整的设计方案。在编写任何代码之前，先完成设计。

## 硬性约束

在用户批准设计之前，禁止编写任何代码、创建任何文件、执行任何实现动作。

## 流程

1. 探索项目上下文

// turbo
```
确认 .windsurf/rules/project-rules.md 已加载
读取文件 .tasks/TASK_TRACKER.md
```

了解当前项目状态、已完成的功能、进行中的任务。如需深度了解某阶段能力，读取对应 `.windsurf/skills/` 文件。

2. 逐一提问澄清

针对用户的想法，每次只问一个问题：
- 这个功能要解决什么问题？
- 目标用户是谁？使用场景是什么？
- 有没有参考案例？
- 有什么技术约束？
- 成功标准是什么？

3. 提出 2-3 个方案

每个方案包含：
- 方案概述（1-2 句话）
- 技术实现路径
- 优点和缺点
- 预估工作量
- 推荐理由（如果推荐）

4. 分段展示设计

将设计拆分为可消化的段落，每段让用户确认后再继续：
- 数据模型 / 类型定义
- UI 交互设计
- 核心逻辑流程
- 边界情况处理
- 测试策略

5. 保存设计文档

```
创建文件 docs/designs/YYYY-MM-DD-<topic>.md
```

包含：需求背景、方案选择、技术设计、实现计划。

6. 自检设计文档

检查是否有：
- 占位符或 TODO 未填写
- 前后矛盾的描述
- 模糊不清的定义
- 超出范围的功能蔓延

7. 用户审批后，转入实现规划

设计获批后，调用 `/writing-plans` workflow 创建实现计划。

## 关键原则

- 先理解，后提议（不要急于给方案）
- 每次只问一个问题（避免信息轰炸）
- 设计可以很简短，但不能跳过（即使看起来很简单的需求）
- 不同意用户方案时，解释理由并提供替代方案
